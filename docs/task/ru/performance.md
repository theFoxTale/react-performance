# React: Производительность

## 🧠 Описание задачи

В этом задании вам предстоит оптимизировать намеренно неоптимизированное React-приложение, которое отображает данные о выбросах CO2. Стартовое приложение **уже включает все функциональные возможности**. Ваша задача — профилировать приложение с помощью React DevTools, выявить узкие места производительности, применить техники оптимизации React и измерить улучшения.

## 🎯 Цели задачи

- Научиться использовать Profiler в React DevTools для выявления узких мест производительности
- Понять и применять техники мемоизации React (`useMemo`, `useCallback`, `React.memo`)
- Научиться оптимизировать рендеринг списков с помощью правильных ключей и виртуализации
- Измерить и задокументировать улучшения производительности до и после оптимизации

## 📚 Часто задаваемые вопросы (FAQ)

### ❓ Можно ли использовать сторонние библиотеки для виртуализации?

Да, можно использовать `react-window`, `react-virtualized` или реализовать свою собственную виртуализацию.

### ❓ Что если мое приложение уже достаточно быстрое?

Стартовое приложение намеренно неоптимизировано, поэтому вы должны явно видеть проблемы с производительностью. Если вы не замечаете проблем, проверьте, что вы используете правильный стартовый код и профилируете в режиме разработки.

### ❓ Следует ли профилировать в режиме разработки или продакшена?

Профилируйте в **режиме разработки** для получения наиболее точных временных характеристик на уровне компонентов. Режим продакшена имеет иные характеристики производительности из-за минификации.

### ❓ Как узнать, работает ли `React.memo`?

Вы можете использовать функцию "Highlight updates when components render" в React DevTools (настройки вкладки Profiler). Компоненты, которые не подсвечиваются при обновлении родителя, правильно мемоизированы.

### ❓ Можно ли использовать React Compiler (автоматическую мемоизацию)?

Нет, цель этого задания — изучить ручные техники оптимизации. Использование React Compiler противоречило бы учебной цели.

### ❓ Стоит ли использовать `useCallback` и `useMemo` везде?

Нет. Эти хуки следует использовать в основном для тяжелых вычислений или предотвращения ненужных повторных рендеров в больших деревьях компонентов. Использование их везде добавляет ненужные накладные расходы на память и усложняет чтение кода. "Преждевременная оптимизация" иногда может замедлить приложение, потому что работа React по сравнению зависимостей не всегда дешевле, чем просто повторный запуск функции.
